# 카드·프로모션 AI 모델 비교 — 2026-10-11

## 판정

현재 구조화 파이프라인에서는 **luna(`gpt-5.6-luna`)를 유지한다.** 같은 날 측정한 `gpt-6-luna`도 아직 바꿀 근거가 부족하다([아래](#gpt-56-luna와-gpt-6-luna)). Claude Opus 5.5는 일부 카드에서 더 나은 범위 판단을 보였지만, 검증 통과율·속도·SKT 완전 수집에서 luna보다 낮았다. 운영 경로에는 Claude 클라이언트를 연결하지 않았고, 같은 입력으로 다시 비교할 수 있는 읽기 전용 도구만 남겼다.

## 방법

- 도구: `scripts/compare-ai-models.ts`. DB를 쓰지 않고, 카드마다 최신 후보의 저장 공식 원문을 같은 프롬프트·후처리·검증·감사에 넣는다. 원본 결과는 작업공간 `experiments/cherrypicker-model-compare-20261011/`에 있다.
- Claude 카드 15장, luna는 두산 1장을 새 프롬프트로 실행했다. 나머지 14장의 luna 수치는 기존 저장 후보를 현재 검증기로 다시 검사한 값이다. 이 후보는 과거 프롬프트와 몇 달간의 파이프라인 보정을 거쳤고 일부는 사람 검수를 마쳤으므로, Claude 첫 실행과 같은 조건이 아니다.
- Claude의 규칙 구조화 호출은 constrained decoding을 쓸 수 없었다. 재귀를 모두 펼치지 않은 경우를 포함해 schema 문법이 너무 크다는 400 응답을 받았다. 그래서 JSON Schema를 프롬프트에 넣고 zod 검증과 1회 오류 피드백 재시도로 실행했다. 혜택 목차 호출은 constrained decoding으로 실행했다. luna는 두 호출 모두 strict structured output이다.
- 프로모션은 공식 페이지를 한 번만 받아 두 모델이 같은 입력을 쓰게 했다. SKT 보조 파서 상한 15회, 적용 범위 분류 상한 25회는 운영값과 같다.

## 함께 발견한 문제

- `card.performancePolicy` schema의 `sourceUrl`이 `format: uri`를 만들어 OpenAI strict 출력이 400을 반환했다. 2026-09-12 추가 이후 실제 수집이 없어 피해는 없었지만, 다음 AI 카드 수집이 전부 실패했을 문제다. `d38e411`에서 수정하고 strict 형식 회귀 테스트를 추가했다.
- Claude structured output은 재귀 schema와 큰 문법을 받지 않는다. 규칙 구조화 schema를 Claude constrained decoding으로 쓰려면 schema를 나누거나 DSL을 별도 호출로 분리해야 한다.

## gpt-5.6-luna와 gpt-6-luna

사용자 요청으로 2026-09-14 출시된 `gpt-6-luna`를 현재 모델과 비교했다. 카드 3장을 모델마다 한 번씩 같은 입력으로 실행했다(모델당 API 6회). 원본은 작업공간 `experiments/cherrypicker-luna-compare-20261011/`에 있다. 비용은 OpenAI 모델 페이지의 `gpt-5.6-luna` $0.20/$1.20, 외부 집계의 `gpt-6-luna` $0.10/$0.50(100만 토큰당 입력/출력)로 추정했다. `gpt-6-luna` 단가는 OpenAI 공식 페이지에서 직접 확인하지 못했다.

| 카드 | 5.6 규칙 / 미게시 / 오류 / 시간 | 6 규칙 / 미게시 / 오류 / 시간 |
| --- | --- | --- |
| 두산베어스 KB | 5 / 0 / 15 / 97초 | 6 / 6 / 3 / 168초 |
| 삼성 iD ON | 10 / 2 / 5 / 153초 | 11 / 7 / 5 / 250초 |
| 신한 Hi-Point | 32 / 1 / 2 / 223초 | 32 / 0 / 5 / 410초 |
| 합계 토큰(입력 / 출력), 추정 비용 | 13.7만 / 5.2만, 약 $0.09 | 14.6만 / 7.9만, 약 $0.05 |

- 두산: 6은 중첩 월 한도 근거 누락이 없고 티켓·굿즈·구장 F&B를 따로 나눈 DSL 6개를 만들었다. 다만 무이자할부·상품권 할인 제외 문구를 등록 패턴이 없어 `NEW`로 표시했고, 정책대로 모든 규칙이 미게시가 됐다. 5.6은 카테고리 ID 대신 이름("생활" 등)을 쓴 오류 5건과 어제와 같은 중첩 한도 근거 누락이 나왔다. 5.6은 같은 입력으로 전날 8건, 이날 15건이라 실행 간 편차가 크다.
- 삼성: 6은 DSL을 하나도 쓰지 않았다. DSL이 지원하는 "이용금액이 가장 큰 영역"과 한도 초과 후 낮은 할인율을 `NEW`로 표시해 11개 중 7개가 미게시가 됐다. 5.6은 DSL 6개를 만들었다.
- Hi-Point: 6은 존재하지 않는 브랜드 ID 3개를 지어냈고, 월 적립 한도 문구에 승인 가맹점 확인 패턴을 붙였다.
- 판정: 6은 토큰당 단가가 낮아 출력이 50% 늘어도 추정 비용이 약 45% 적지만, 1.7~1.8배 느리고 DSL을 덜 쓰며 패턴과 ID 오용이 있다. 표본이 3장 1회뿐이고 실행 간 편차가 커서 교체하지 않는다. 할인 제외 거래 패턴을 등록한 뒤 같은 3장으로 한 번 더 비교할 수 있다.
