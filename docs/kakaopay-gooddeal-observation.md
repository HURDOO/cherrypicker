# 카카오페이 굿딜 관측 경로 검증

검증일: 2026-10-11. 사용자의 안드로이드 실기기(Android 16, 카카오페이 앱 26.8.10)를 USB adb로 연결해 확인했다. 이 문서는 검증 결과와 폰 전용 관측 앱의 구현·첫 실행 기록이다. 수집 결과의 카탈로그 반영이나 수집 정책 변경을 뜻하지 않는다. 작업 상태는 [TASKS.md](./TASKS.md)의 TASK-12에서 관리한다.

## 결론

- 공식 웹과 공개 API로는 현재 브랜드별 굿딜 할인율을 받을 수 없다.
- 앱의 굿딜 홈은 WebView이며, 접근성 트리에 전체 브랜드 목록이 텍스트로 노출된다. 링크 하나로 굿딜 홈을 열고 한 번 읽으면 전체 목록을 얻는다(관측 시점 106개). OCR과 스크롤은 필요 없다.
- 폰 전용 관측 앱을 만들어 2026-10-11부터 1주 동안 폰 내부에만 기록한다. 변동 빈도를 확인한 뒤 서버 연동 여부를 정한다.

| 화면 캡처 | 차단되지 않는다(`FLAG_SECURE` 미설정). 텍스트를 읽을 수 있으므로 OCR은 쓰지 않는다. |
| 기간·한도 | 목록에는 없다. 브랜드 상세에 있지만 바코드와 함께 렌더링되므로 진입하지 않는다. |

2026-10-11 14시대에 한 계정으로 본 관측값은 다음과 같다.

- 전체 목록 106개. 할인율 분포는 2%(8) · 3%(23) · 4%(38) · 5%(19) · 6%(3) · 7%(10) · 8%(1) · 10%(3) · 20%(1)이다.
- `혜택` 표시가 붙은 행사 항목: 세븐일레븐 10%, 이마트24 10%, 더벤티 10%, 쉐이크쉑 20%
- 배너 문구 예: `이마트24에서는 매일 10% 할인`, `쉐이크쉑 전메뉴 무제한 20% 할인`, `10대를 위한 굿딜 틴즈 10% 할인 혜택`

한 계정에서 관측한 값이므로 모든 사용자에게 같은 율인지는 확인하지 않았다. 화면 상단의 `<이름>님을 위한 추천` 영역은 개인화 영역이다. 이 영역에는 사용자 이름과 `최근 결제` 표시가 붙은 최근 결제 브랜드가 함께 나온다. 수집에서 제외한다.

## 앱 링크

| 링크 | 열리는 화면 | 사용 여부 |
| --- | --- | --- |
| `kakaopay://payweb?url=https%3A%2F%2Fgood-deal-web.kakaopay.com%2Fhome%2Fall` | 굿딜 홈(`PayWebActivity`) | 관측에 사용한다. 홈 화면에서 실행해 결제 화면을 거치지 않고 열렸고, 5초 뒤 전체 목록을 확인했다. |
| `kakaopay://payment/…` | 오프라인 결제 화면(`com.kakaopay.feature.payment.offline.presentation.PayOfflineActivity`) | 관측에는 사용하지 않는다. 결제 코드가 생성되는 화면이라 수집 중 실행하면 위험하다. 나중에 체리피커에서 결제수단으로 바로 이동하는 버튼을 만들 때 참고할 수 있다. 시스템 로그가 경로 뒤를 가려 정확한 경로는 확인하지 않았다. |
| `https://link.kakaopay.com/t/payweb?url=…` | 앱에 직접 열리지 않는다. | 공식 소개 페이지의 버튼 링크다. 앱이 `/t/` 경로를 intent filter에 등록하지 않아 `am start`로 실행되지 않는다. |

홈 화면의 굿딜 위젯(`PayAppWidgetPaymentGoodDealMediumReceiver`)은 Glance 기반이다. 탭하면 앱 내부 콜백을 거쳐 위 두 `kakaopay://` 링크 중 하나로 이동한다. 결제 영역은 `payment`, 굿딜 홈 영역은 `payweb`이다.

## 개인정보 처리 규칙

실기기 확인에서 아래 규칙을 적용했고, 관측 앱도 같은 규칙을 따른다.

- 접근성 트리와 캡처를 파일로 저장하지 않는다. `uiautomator dump /dev/tty`로 폰에도 파일을 만들지 않았고, 맥에서는 메모리에서 바로 필터링했다.
- 허용 패턴(`N% 할인` 항목과 카테고리 이름)만 출력한다. `님`이나 `최근 결제`가 들어간 텍스트는 내용을 보지 않고 버린다. 나머지 텍스트는 개수만 센다.
- 결제·바코드 화면과 브랜드 상세는 열지 않는다. 카카오페이 화면을 탭하거나 제스처를 보내지 않는다.

검증 환경 메모: 이 맥의 에이전트 셸은 로컬 네트워크 접근이 막혀 무선 디버깅 페어링이 `protocol fault`로 실패했다. 그래서 USB로 연결했다.

## 폰 전용 관측 앱

`/Users/hurdoo/coding/experiments/kakaopay-gooddeal-observer`에 있다. 작업공간의 일회성 검증 폴더이며 체리피커 저장소 밖에 둔다. 자체 로컬 Git 저장소이고 원격은 없다. 빌드·설치·사용법은 그 폴더의 `README.md`에 있다.

### 동작

1. 앱의 [굿딜 읽기] 버튼을 누르면 `kakaopay://payweb` 링크로 굿딜 홈을 연다.
2. 접근성 서비스가 1.5초 뒤부터 1초 간격으로 최대 20초 동안 화면을 읽는다. 앞 창이 `com.kakaopay.app`일 때만 읽는다.
3. 목록이 50개 이상이고 두 번 연속 같으면 관측을 확정한다. 아니면 실패 이유와 함께 기록한다.
4. 트리를 복사하는 순간 `님`이나 `최근 결제`가 들어간 텍스트를 버린다. 그다음 `(혜택 )?브랜드 N% 할인` 버튼이 가장 길게 연속된 묶음만 목록으로 쓴다. 추천 영역은 별도 묶음이라 빠진다. 배너는 `top-banner` 영역의 `%` 문구만 저장한다.
5. 앱 전용 저장소의 `files/observations.jsonl`에 한 줄씩 추가한다. 원본 접근성 트리와 캡처는 저장하지 않는다.
6. 앱으로 돌아와 직전 성공 관측 대비 변경을 보여주고, 그 아래에 전체 브랜드를 할인율별로 보여준다.
7. [내보내기]를 누르면 시스템 저장 위치 선택 화면을 열고, 사용자가 고른 위치에 파일을 쓴다. 기록이 쌓이면 공유 메뉴로 넘기기엔 커질 수 있어 이 방식으로 바꿨다. USB로 연결했을 때는 `adb exec-out run-as dev.hurdoo.gooddealobserver cat files/observations.jsonl`로도 꺼낸다.

```json
{"observedAt":"2026-10-11T16:40:21+09:00","kakaopayVersion":"26.8.10","parserVersion":1,"status":"ok","reason":null,
 "itemCount":106,"items":[{"brand":"세븐일레븐","rate":10,"boosted":true}],"banners":["이마트24에서는 매일 10% 할인 지금 확인하기"]}
```

### 안전장치

- 앱이 권한을 하나도 선언하지 않는다(`aapt2 dump permissions` 결과 없음). 관측 데이터는 사용자가 내보내기 전까지 폰 밖으로 나가지 않는다. 백업과 기기 이전에서도 앱 데이터를 제외한다.
- 카카오페이에 보내는 동작은 `payweb` 링크 열기뿐이다. 접근성 서비스는 읽기만 하며 제스처, 노드 클릭, 스크롤, 키 입력 가로채기를 쓰지 않는다. `payment` 링크와 브랜드 상세는 코드에 넣지 않았다.
- 잠금이나 재인증 화면은 사용자가 처리한다. 20초 안에 목록을 확정하지 못하면 실패로 남기고 끝낸다.
- 링크나 화면 구조가 바뀌면 실패(`kakaopay_not_visible`, `too_few_items`, `unstable`)로 드러난다. 추정값을 저장하지 않는다.
- logcat에는 상태와 개수만 남긴다.

### 확인한 운영 주의점

- 맥에서 `uiautomator dump`를 실행하는 동안에는 시스템이 다른 접근성 서비스를 잠시 끈다. 이때 앱 화면이 "꺼짐"으로 보이므로, 앱 상태 확인은 사용자가 화면을 직접 본다.
- 앱을 갱신 설치하면 접근성 서비스가 다시 연결되기까지 몇 초가 걸린다. 앱 화면은 서비스 연결 상태가 바뀔 때 다시 그린다.
- 이 폰은 삼성 보안 위험 자동 차단 때문에 USB 디버깅이 약 30분 뒤 꺼질 수 있다. 관측은 폰만으로 하므로 영향이 없고, 기록을 맥으로 옮길 때만 다시 켠다.

### 1주 사용 후 판단

- 브랜드별 할인율 변경 횟수와 변경 시각
- `혜택` 행사가 붙고 빠지는 시점
- 목록의 브랜드 증감
- 서버 연동 여부와 관측 주기. 연동하려면 `promotion-source-policy.md`의 앱 내부 수집 제외에 대한 예외, 관측 근거 형식, 개인화 영역 제외, 관측 시각 표시 기준을 [DECISIONS.md](./DECISIONS.md)에서 결정해야 한다.

## 미검증 항목

- 할인율이 사용자마다 같은지
- 하루 중 할인율 변동 빈도
