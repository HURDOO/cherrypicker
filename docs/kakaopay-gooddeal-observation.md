# 카카오페이 굿딜 관측 경로 검증

검증일: 2026-10-11. 사용자의 안드로이드 실기기(Android 16, 카카오페이 앱 26.8.10)를 USB adb로 연결해 확인했다. 이 문서는 검증 결과와 폰 전용 관측 앱 제안이다. 수집 결과의 카탈로그 반영이나 수집 정책 변경을 뜻하지 않는다. 작업 상태는 [TASKS.md](./TASKS.md)의 TASK-12에서 관리한다.

## 결론

- 공식 웹과 공개 API로는 현재 브랜드별 굿딜 할인율을 받을 수 없다.
- 앱의 굿딜 홈은 WebView이며, 접근성 트리에 전체 브랜드 목록이 텍스트로 노출된다. 링크 하나로 굿딜 홈을 열고 한 번 읽으면 전체 목록을 얻는다(관측 시점 106개). OCR과 스크롤은 필요 없다.
- 폰 전용 관측 앱으로 1주 동안 폰 내부에만 기록해 변동 빈도를 확인한 뒤 서버 연동 여부를 정한다.

## 공개 웹 확인 결과

| 대상 | 결과 |
| --- | --- |
| `good-deal-web.kakaopay.com` | Next.js 서버 렌더링 앱이다. 쿠키 없이 요청하면 `/`와 `/home/all` 모두 HTTP 500이며, 모바일 브라우저 User-Agent로도 같다. 빌드 manifest에는 `_app`과 `_error`만 있어 공개 정적 페이지가 없다. 앱 로그인 정보를 전제로 렌더링하는 구조로 판단한다. |
| `contents.kakaopay.com` | sitemap에 글 1,438개가 있고 거의 매일 갱신된다. 2026-09-01~10-11 글 45개 중 굿딜 글은 0개였다. 굿딜 글은 출시 소개(`/contents/2385`)와 기간 행사(`/contents/2426`)처럼 간헐적으로만 있다. |
| `www.kakaopay.com` | sitemap의 11개 URL이 서비스 소개이며 혜택 목록이 없다. |
| 보도 | 기본 정률 할인에 기간 한정 추가율을 더하는 구조다. 예: 세븐일레븐은 기본 3%, 10월 31일까지 최대 10%, 하루 1회 최대 5천 원([SBS Biz, 2026-08-19](https://biz.sbs.co.kr/amp/article/20000329398)). 결제 시점에 상품권을 즉시 발행하고 브랜드마다 바코드를 따로 만든다([바이라인네트워크, 2025-03](https://byline.network/2025/03/23-412/)). |

`src/lib/promotion-collector.ts`의 `kakaopay-benefits`와 `kakaopay-gooddeal`은 계속 `unsupported`로 둔다.

## 앱 실기기 확인 결과

| 항목 | 결과 |
| --- | --- |
| USB 디버깅 상태에서 실행 | 경고나 차단 없이 실행된다. |
| 굿딜 홈 화면 | `com.kakaopay.android.web.presentation.PayWebActivity`(WebView)다. |
| 접근성 트리 | `uiautomator dump` 한 번에 전체 목록이 나온다. 화면 밖 항목도 포함되어 스크롤이 필요 없다. |
| 항목 형식 | 텍스트 노드 하나에 `브랜드 N% 할인`이 함께 있다. 행사 항목은 `혜택 브랜드 N% 할인`이다. |
| 화면 캡처 | 차단되지 않는다(`FLAG_SECURE` 미설정). 텍스트를 읽을 수 있으므로 OCR은 쓰지 않는다. |
| 기간·한도 | 목록에는 없다. 브랜드 상세에 있지만 바코드와 함께 렌더링되므로 진입하지 않는다. |

2026-10-11 14시대에 한 계정으로 본 관측값은 다음과 같다.

- 전체 목록 106개. 할인율 분포는 2%(8) · 3%(23) · 4%(38) · 5%(19) · 6%(3) · 7%(10) · 8%(1) · 10%(3) · 20%(1)이다.
- `혜택` 표시가 붙은 행사 항목: 세븐일레븐 10%, 이마트24 10%, 더벤티 10%, 쉐이크쉑 20%
- 배너 문구 예: `이마트24에서는 매일 10% 할인`, `쉐이크쉑 전메뉴 무제한 20% 할인`, `10대를 위한 굿딜 틴즈 10% 할인 혜택`

한 계정에서 관측한 값이므로 모든 사용자에게 같은 율인지는 확인하지 않았다. 화면 상단의 `<이름>님을 위한 추천` 영역은 개인화 영역이다. 이 영역에는 사용자 이름과 `최근 결제` 표시가 붙은 최근 결제 브랜드가 함께 나온다. 수집에서 제외한다.

## 앱 링크

| 링크 | 열리는 화면 | 사용 여부 |
| --- | --- | --- |
| `kakaopay://payweb?url=https%3A%2F%2Fgood-deal-web.kakaopay.com%2Fhome%2Fall` | 굿딜 홈(`PayWebActivity`) | 관측에 사용한다. 홈 화면에서 실행해 결제 화면을 거치지 않고 열렸고, 5초 뒤 전체 목록을 확인했다. |
| `kakaopay://payment/…` | 오프라인 결제 화면(`com.kakaopay.feature.payment.offline.presentation.PayOfflineActivity`) | 관측에는 사용하지 않는다. 결제 코드가 생성되는 화면이라 수집 중 실행하면 위험하다. 나중에 체리피커에서 결제수단으로 바로 이동하는 버튼을 만들 때 참고할 수 있다. 시스템 로그가 경로 뒤를 가려 정확한 경로는 확인하지 않았다. |
| `https://link.kakaopay.com/t/payweb?url=…` | 앱에 직접 열리지 않는다. | 공식 소개 페이지의 버튼 링크다. 앱이 `/t/` 경로를 intent filter에 등록하지 않아 `am start`로 실행되지 않는다. |

홈 화면의 굿딜 위젯(`PayAppWidgetPaymentGoodDealMediumReceiver`)은 Glance 기반이다. 탭하면 앱 내부 콜백을 거쳐 위 두 `kakaopay://` 링크 중 하나로 이동한다. 결제 영역은 `payment`, 굿딜 홈 영역은 `payweb`이다.

## 개인정보 처리 규칙

실기기 확인에서 아래 규칙을 적용했고, 관측 앱도 같은 규칙을 따른다.

- 접근성 트리와 캡처를 파일로 저장하지 않는다. `uiautomator dump /dev/tty`로 폰에도 파일을 만들지 않았고, 맥에서는 메모리에서 바로 필터링했다.
- 허용 패턴(`N% 할인` 항목과 카테고리 이름)만 출력한다. `님`이나 `최근 결제`가 들어간 텍스트는 내용을 보지 않고 버린다. 나머지 텍스트는 개수만 센다.
- 결제·바코드 화면과 브랜드 상세는 열지 않는다. 카카오페이 화면을 탭하거나 제스처를 보내지 않는다.

검증 환경 메모: 이 맥의 에이전트 셸은 로컬 네트워크 접근이 막혀 무선 디버깅 페어링이 `protocol fault`로 실패했다. 그래서 USB로 연결했다.

## 폰 전용 관측 앱 제안

위치는 작업공간의 일회성 검증 폴더인 `/Users/hurdoo/coding/experiments/kakaopay-gooddeal-observer`다. 체리피커 저장소 밖에 둔다.

### 동작

1. 앱의 [굿딜 읽기] 버튼을 누르면 `kakaopay://payweb` 링크로 굿딜 홈을 연다.
2. 앱의 접근성 서비스는 `com.kakaopay.app`만 대상으로 하고, 버튼을 누른 뒤 20초 동안만 화면을 읽는다.
3. 두 번 연속 읽은 항목 수가 같고 50개 이상이면 관측을 확정한다. 아니면 실패로 기록한다.
4. `(혜택 )?브랜드 N% 할인` 패턴만 추출한다. 개인화 영역, `님`, `최근 결제` 텍스트는 폰 안에서 버린다. 배너 문구는 별도 필드에 둔다.
5. 앱 전용 저장소의 `observations.jsonl`에 한 줄씩 추가한다. 원본 접근성 트리와 캡처는 저장하지 않는다.
6. 앱으로 돌아와 직전 관측과 달라진 항목만 보여준다.
7. [내보내기] 버튼으로 공유 메뉴를 열어 사용자가 직접 파일을 옮긴다.

```json
{"observedAt":"2026-10-11T14:50:03+09:00","kakaopayVersion":"26.8.10","parserVersion":1,"status":"ok",
 "itemCount":106,"items":[{"brand":"세븐일레븐","rate":10,"boosted":true}],"banners":["이마트24에서는 매일 10% 할인"]}
```

### 안전장치

- 인터넷 권한을 선언하지 않는다. 관측 데이터는 사용자가 내보내기 전까지 폰 밖으로 나가지 않는다.
- 카카오페이에 보내는 동작은 `payweb` 링크 열기뿐이다. 접근성 서비스는 읽기만 하며 `dispatchGesture`와 노드 클릭을 쓰지 않는다. `payment` 링크와 브랜드 상세는 코드에 넣지 않는다.
- 잠금이나 재인증 화면은 사용자가 처리한다. 20초 안에 목록을 확정하지 못하면 실패로 남기고 끝낸다.
- 링크나 문구 형식이 바뀌면 항목 0개 또는 실패로 드러나게 한다. 추정값을 저장하지 않는다.

### 확인할 위험

- 접근성 서비스가 켜져 있을 때 카카오페이가 보이스피싱 대응 경고를 띄우거나 실행을 막을 수 있다. 문제가 되면 관측할 때만 설정에서 서비스를 켠다.
- Android 13 이상에서는 스토어 밖에서 설치한 앱에 접근성 권한을 주기 전에 '제한된 설정 허용'이 필요하다.
- 빌드에는 맥의 Android SDK·JDK·Gradle이 필요하다. 설치는 USB adb로 한 번 한다.

### 1주 사용 후 판단

- 브랜드별 할인율 변경 횟수와 변경 시각
- `혜택` 행사가 붙고 빠지는 시점
- 목록의 브랜드 증감
- 서버 연동 여부와 관측 주기. 연동하려면 `promotion-source-policy.md`의 앱 내부 수집 제외에 대한 예외, 관측 근거 형식, 개인화 영역 제외, 관측 시각 표시 기준을 [DECISIONS.md](./DECISIONS.md)에서 결정해야 한다.

## 미검증 항목

- 할인율이 사용자마다 같은지
- 하루 중 할인율 변동 빈도
- 접근성 서비스가 켜진 상태에서 카카오페이의 반응
- 행사 조건(기간·한도)을 바코드 화면 없이 확보하는 방법
