# 혜택 반영 단계와 미지원 규칙·브랜드 대응 정책

- 상태: 승인 — 2026-10-10 사용자 결정. 구현은 `TASK-10`에서 진행한다.
- 적용 대상: 카드 혜택 후보, 프로모션이 발견한 브랜드, 카드 후보가 참조하는 결제처
- 관련 문서: [`card-benefit-source-policy.md`](./card-benefit-source-policy.md), [`card-benefit-dsl-v1.md`](./card-benefit-dsl-v1.md), [`promotion-source-policy.md`](./promotion-source-policy.md)

## 1. 원칙

카드가 늘수록 앱이 아직 계산하지 못하는 규칙과 등록되지 않은 결제처가 계속 등장한다. 모든 문구를 계산할 수 있을 때까지 카드 전체를 막지 않고, **과대 계산만 막는다.** 혜택을 덜 보여주는 쪽의 오차는 안내 문구로 보완하고, 실제보다 많이 보여주거나 추천 순위를 부풀리는 오차만 차단한다.

## 2. 반영 단계

| 단계 | 기준 | 사용자 표시 |
| --- | --- | --- |
| 자동 계산 | 금액·조건·한도를 결제금액·결제처·채널·시각·실적·이용 기록 등 현재 입력만으로 판정한다. | `확정` |
| 조건 확인 | 앱은 알 수 없지만 결제 순간 사용자가 예/아니오로 답할 수 있다. 지정 판매처, 행사 상품, 승인 업종·PG 제외, 자동이체 여부가 해당한다. | `조건 충족 시` |
| 정보 제공 | 원화 금액으로 바꿀 수 없거나 일상 결제 추천과 관계가 낮다. | 0원과 공식 조건 문구. 규칙이 결제처를 지정하면 그 결제처의 추천 결과에 `내 카드의 다른 혜택`으로 표시 |
| 카드 주의 문구 | 개별 혜택이 아니라 카드 전체에 걸리는 조건이며 앱이 판정할 수 없다. | 카드·실적 안내의 한 줄 문구 |
| 게시 차단 | 위 단계로 내려도 과대 계산을 막을 수 없다. | 해당 규칙 미게시 |

### 정보 제공으로 고정하는 항목

1. 외부 변수에 따라 금액이 정해지는 혜택: 주유 리터당 할인·적립, 환율, 해외 이용·ATM 수수료
2. 현금이 아닌 혜택: 공항 라운지, 무료 제공, 보험, 쿠폰·사은품, 마일리지
3. 금융상품 혜택: 우대금리, 수수료 면제
4. 응모·추첨·선착순 행사
5. 한 문구에 요율이 여럿이고 현재 사용자 프로필로 하나를 정할 수 없는 혜택
6. 연 1~2회 수준의 저빈도 혜택: 테마파크 연간 횟수, 생일 혜택 등

특정 상품 할인(편의점 행사상품 등)은 기존처럼 `조건 충족 시`로 표시하고, 사용자가 대상 상품 금액을 입력하면 계산한다.

국군의날·현충일처럼 매년 날짜가 정해진 혜택은 저빈도라도 정보 제공으로 두지 않고 반복 날짜 조건(`annualDates`, 그날 빠지는 일반 혜택은 `excludedAnnualDates`)으로 그 날짜에만 계산한다.

## 3. 규칙 단위 게시

- 금액·조건·한도에 영향을 주는 미지원 문구는 연결된 `ruleIds`의 규칙만 낮춘다. 같은 카드의 나머지 규칙은 검증을 통과하면 게시한다.
- 낮추는 순서는 `조건 확인` → `정보 제공` → `게시 차단`이다. 사용자 질문 하나로 과대 계산을 막을 수 있으면 조건 확인, 그렇지 않으면 0원 정보 제공으로 둔다.
- 낮춘 규칙이 다른 규칙과 한도를 공유하는 등 정보 제공으로도 다른 계산을 부풀릴 수 있으면 해당 규칙과 공유 그룹만 게시에서 제외하고 카드 지원 범위에 `미반영 혜택`으로 표시한다.
- 카드 통합 한도처럼 카드의 모든 계산 규칙을 제한하는 문구를 표현할 수 없으면 모든 계산 규칙이 영향을 받으므로 카드 게시를 보류한다.
- 낮춘 규칙과 미게시 규칙은 확정 총액과 기본 추천 순위에 포함하지 않는다.

### 카드 실적 제외

공식 실적 제외 중 앱이 거래 종류를 판정할 수 없는 항목(무이자할부, 상품권, 세금 등)은 게시를 막지 않고 카드 주의 문구로 안내한다. 예상 실적은 기존처럼 승인금액 기준으로 반영하고 판정 가능한 제외만 적용한다. 사용자는 기존 수동 실적 보정으로 바로잡을 수 있다. 결제 기록 단계에 거래 종류 입력을 추가하지 않는다.

할인·적립에서 빠지는 거래 종류(무이자할부, 상품권·선불카드 구입·충전, 취소, 해외 이용 등)와 카드사의 다른 청구할인과 중복되지 않는다는 문구도 같은 이유로 카드 주의 문구로 안내한다. 이 문구들은 거의 모든 카드에 있어 조건 확인으로 낮추면 모든 혜택이 확정에서 빠진다.

## 4. 미지원 패턴

- 미지원 문구는 자유 텍스트만이 아니라 등록된 **패턴 ID**를 가진다(예: `PERF_EXCLUDE_INSTALLMENT`, `PG_EXCLUDED`).
- 패턴은 의미, 반영 단계, 사용자 문구와 일상 카테고리 여부를 정의한다. 같은 패턴은 모든 카드에서 같은 단계와 문구로 처리한다.
- AI 후보는 등록된 패턴을 선택하거나 새 패턴을 제안한다. 새 패턴은 검수에서 등록하기 전까지 해당 규칙을 게시하지 않는다.
- 카드별 정규식 검증을 새로 추가하지 않는다. 기존 카드 전용 검증은 패턴 또는 범용 검증으로 옮긴다.

### 엔진 확장 검토 기준

- 일상 카테고리 결제처에 걸린 패턴은 게시 카드 1장에서 나와도 DSL 확장을 검토한다. 일상 카테고리는 `PROJECT_BRIEF.md` §8의 편의점·카페·마트·다이소·올리브영·교통·통신·온라인 쇼핑과 외식·배달이다.
- 그 밖의 패턴은 같은 패턴 ID가 게시 카드 3장 이상에서 나올 때 검토한다.
- 검토 전까지는 위 반영 단계로 처리한다. 확장은 범용 입력·연산자로만 하며 카드 ID 분기를 만들지 않는다.

## 5. 브랜드

| 대상 | 처리 |
| --- | --- |
| 식별 가능한 실제 매장·온라인몰 | 카드 후보가 이름·카테고리·별칭·공식 인용과 함께 새 브랜드를 제안한다. 기존 브랜드와 별칭 매칭으로 중복을 먼저 확인하고, 혜택 승인 트랜잭션에서 브랜드와 규칙을 함께 등록한다. 미승인 후보의 브랜드는 공개 카탈로그에 넣지 않는다. |
| 경기·상품·장소 등 매장이 아닌 범위 | 기존처럼 근거 있는 `purchaseScenario`로 표현한다. |
| 열거할 수 없는 판매처 집합 | 카테고리와 확인 질문으로 `조건 충족 시` 처리하며 카테고리 전체 확정 혜택으로 넓히지 않는다. |

### 검색 전용 노출

새로 추가되는 브랜드는 카드·프로모션 출처와 관계없이 **자동 노출**(`AUTO`)로 저장하고, 공개 catalog를 만들 때마다 현재 혜택으로 노출을 정한다. 혜택이 없으면 검색 전용이다.

- 탐색 목록에 노출: 게시 카드의 금액 계산 혜택(0원 정보 제외)이 걸린 브랜드, 또는 일상 카테고리(편의점·카페·외식·배달·교통·쇼핑·구독)에서 진행 중인 프로모션이 있는 브랜드
- 검색 전용: 그 밖의 경우. 프로모션이 끝나거나 혜택이 0원 정보뿐이면 다시 숨는다.
- 검색 전용에서 숨김: 카테고리 목록, 전체 목록, 기본 인기 목록
- 검색 전용에서도 노출: 이름·별칭·초성 검색, 즐겨찾기, 최근·자주 이용, 개인 혜택 제안
- 사용자가 즐겨찾기하거나 이용하면 해당 사용자의 개인 목록에서 기존 순위 규칙대로 올라온다.
- seed·큐레이션 브랜드는 `BROWSE`로 항상 노출한다. 관리자가 특정 브랜드를 항상 숨기려면 `SEARCH_ONLY`로 고정한다.
- 자동 판정의 정확도는 브랜드 카테고리에 달려 있다. 새 브랜드의 카테고리는 이름을 먼저 보고, 이름으로 정할 수 없을 때만 출처의 분류 힌트를 쓴다.

## 6. 구현 상태

2026-10-10 구현:

- 패턴 registry와 규칙 단위 변환은 `src/lib/benefit-coverage-patterns.ts`에 있다. 패턴 추가는 이 파일의 검토된 코드 변경으로 한다.
- 검증기·후보 audit·승인은 변환을 적용한 게시 형태를 기준으로 한다. 이미 게시된 규칙이 미등록 패턴으로 제외되면 audit에 고위험 삭제로 나타난다.
- 카드 주의 문구와 제외 규칙은 revision snapshot `coverage`에 저장되어 공개 카드 지원 정보의 `caveats`로 나간다. rollback revision도 같은 snapshot을 복사한다.
- AI 구조화 schema·prompt는 `patternId`를 요구한다. 기존 AI cache key는 바꾸지 않았으므로 원문 의미가 같은 카드의 기존 결과는 재호출 없이 재사용되며, 그 결과의 미지원 문구는 패턴이 없어 연결 규칙이 게시에서 제외된다.

- 브랜드 노출 속성 `brands.discovery_visibility`(migration 0020)를 추가했다. 프로모션 자동 발견·관리자 등록·카드 후보 제안으로 생기는 새 공용 브랜드는 검색 전용이며, 기존 브랜드는 모두 `BROWSE`로 유지했다. 홈 탐색과 즐겨찾기 선택기는 검색 전용 브랜드를 탐색 목록에서 빼고 검색·즐겨찾기·이용 기록·개인 혜택 제안으로만 보여준다.
- 카드 후보는 `proposedBrands`로 새 매장을 제안한다. 서버가 기존 브랜드와 이름·별칭을 맞춰 재사용하거나 프로모션과 같은 `official_<hash>` ID를 부여한다. 감사에 고위험 추가로 표시되고, 승인 시 게시 규칙이 참조하는 제안만 등록한다. 브랜드 별칭은 매칭에만 쓰고 별도 저장하지 않는다.

2026-10-11 보정:

- 모델 비교에서 카드 보류 패턴이 할인 제외 거래와 중복 불가 문구에 잘못 쓰이고, 할인 제외 거래가 `NEW`로 표시되어 두산의 모든 규칙이 미게시가 됐다. 할인 제외 거래(`DISCOUNT_EXCLUDE_TRANSACTION_TYPE`)와 카드사 다른 행사 중복 불가(`CARD_OFFER_NO_STACKING`)를 카드 주의 문구 패턴으로 추가하고, 카드 보류 패턴(`CARD_WIDE_LIMIT_UNMODELED`) 설명을 DSL 카드 한도로 표현할 수 없는 통합 한도로 좁혔다.

- 카드 원문 전용 검증(스타벅스 사이렌오더, GS25 해군마트, 신한 SOL 기본 정보·규칙 일치)을 제거했다. 게시 카드 대비 누락·변경은 카드와 무관한 후보 감사의 고위험 변경으로 검수한다.
- 기존 게시 카드 14장을 반영 단계·패턴으로 재분류했다([재분류 결과](./benefit-coverage-reclassification-2026-10-11.md)). 반복 빈도에 따라 자동이체·정기결제(`RECURRING_PAYMENT`)와 카드 보유자 조건(`CARDHOLDER_CONDITION`)을 확인 패턴으로 추가하고, 결제 경로 패턴 설명을 입점 매장·사이트 직접 접속까지 넓혔다.

- 2026-10-11 사용자 확인에 따라 기존 브랜드 노출을 재분류했다. 저장값에 `AUTO`를 추가하고 프로모션·카드 후보로 생긴 `official_` 브랜드 206개를 `AUTO`로 바꿨으며, 잘못 분류된 18개의 카테고리를 고쳤다(migration 0021). 같은 날 기준 48개가 탐색 목록, 158개가 검색 전용이다. 새 브랜드 카테고리 추론은 이름 우선으로 바꾸고 면세점·하이마트·전자랜드를 쇼핑으로 먼저 판정한다.

- 2026-10-11 사용자 승인으로 재분류 결과를 카드 9장의 재검수로 반영했다(revision 3). AI를 호출하지 않고 승인된 후보에 [수정안](./card-benefit-revisions/2026-10-11-coverage-reclassification.json)만 적용해 기존 검증·감사·승인 경로를 거쳤다. 확정 44 → 67, 조건부 104 → 83, 0원 정보 68개다.
- 결제처가 지정된 0원 정보 혜택은 추천 결과의 `내 카드의 다른 혜택`에 금액 없이 표시한다. 결제처 없는 정보 혜택(보험·금리·경조사 등)은 카드 상세에만 둔다. 0원 정보 혜택은 결제처를 지정하지 않으면 카테고리 전체에 걸리지 않고 `추가 상품 행사`에도 넣지 않는다.
- 공개 catalog 브랜드 응답이 검색 전용 표시를 빠뜨려 비로그인 탐색 목록이 모든 브랜드를 보여주던 문제와, 로그인 app-data가 `AUTO`를 모두 검색 전용으로 내보내던 문제를 고쳤다. 두 응답 모두 같은 자동 노출 판정을 쓴다.

아직 구현하지 않은 항목:

- 게시 카드별 패턴 집계를 관리자 화면에 표시하지 않는다. 집계는 재분류 문서로 대신한다.
- 검증이 아닌 카드 ID별 후처리(9장)와 신한 SOL 규칙 기반 추출기가 남아 있다.
