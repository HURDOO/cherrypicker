# 프로모션 원문 수집·검수 정책

프로모션 수집기는 SKT·U+·Npay·T우주와 공개 제휴 페이지의 HTML·JSON 응답을 구조화하기 전에 원문 document와 source bundle로 보존한다. 파서나 AI가 만든 요약문만으로 후보를 승인하지 않으며, 게시 중인 혜택을 비교 기준으로 삼아 계산 조건의 누락과 공식 근거 연결 상태를 검수한다.

## 수집 범위

- 로그인 없이 접근 가능한 공식 웹 페이지와 공개 API만 자동 수집한다.
- 앱 내부, 로그인, CAPTCHA 또는 비공개 API가 필요한 혜택은 자동 수집하지 않는다.
- 사용자 프로필·결제 기록·계정 데이터는 수집기나 AI 분류기에 전달하지 않는다.
- 수집 요청은 문서별 4 MiB, 한 source bundle 합계 32 MiB, 요청당 20초로 제한한다.

## 원문과 source bundle 보존

`promotion_source_documents`는 collection source ID, 요청 URL, media type, SHA-256 content hash, 원문, 검색용 추출 텍스트, ETag·Last-Modified·최종 URL, 수집 시각과 URL별 단조 증가 version을 저장한다. 같은 source ID·URL·hash의 응답은 새 version을 만들지 않는다.

한 번의 출처 수집에 사용한 문서 집합은 `promotion_source_bundles`와 `promotion_source_bundle_documents`로 묶는다. 정렬한 URL·content hash 집합의 hash가 같으면 기존 bundle을 재사용한다. 후보는 `sourceBundleHash`로 자신을 만든 원문 묶음에 연결된다. 공개 카탈로그에는 원문, 내부 후보, 감사 결과와 검수자 정보를 포함하지 않는다.

## 후보 감사와 게시 차단

구조화 후보는 현재 게시본이 있으면 게시본을, 없으면 같은 source key의 직전 후보를 기준으로 필드 diff를 만든다. 브랜드·카테고리·채널·기간·혜택 값·계산 방식·최소 결제·결제수단 호환·한도는 고위험 경로로 취급한다.

파서와 의미 분류기가 제시한 근거 문장이 보존된 원문의 추출 텍스트에 실제로 포함되는지 정규화 후 확인하고, 계산에 쓰이는 주요 필드를 해당 source document와 연결한다. 이 연결은 후보가 공식 원문에서 파생됐다는 추적 가능성을 보장하지만 문장의 의미가 모든 필드를 완전히 입증한다는 뜻은 아니다. 복합 조건과 모호한 표현은 기존 규칙대로 사람 검수를 거친다.

다음 후보는 게시할 수 없다.

- 게시본의 고위험 계산 필드가 새 후보에서 삭제된 경우
- 계산 필드에 연결할 수 있는 공식 원문 근거 문장이 없는 경우
- source bundle 감사 기록이 없는 기존 자동 수집 후보
- 적용 범위가 매장 전체·카테고리·상품·고객 한정 중 하나로 확정되지 않은 경우

관리자가 직접 만든 후보는 공식 source bundle 감사 대상에서 제외하지만, 적용 범위와 기존 입력 검증은 동일하게 적용한다. 감사 차단 후보는 원문·adapter·파서를 보완한 뒤 다시 수집해야 한다.

## 삭제 감지

공식 출처를 정상적으로 모두 수집했는데 기존 자동 게시 혜택이 관측되지 않아도 즉시 만료시키지 않는다. 기존 게시본은 유지하고, 실제 혜택을 만들었던 출처의 최신 source bundle에 연결된 `삭제 의심` 후보를 검수 큐에 만든다. 운영자가 공식 원문을 확인해 `사라짐 확정·만료`를 선택하면 삭제 후보를 승인하고 연결된 게시 혜택을 `EXPIRED`로 바꾸며 reviewer·처리 시각·source bundle hash를 함께 기록한다. 수집 누락이면 `오탐·혜택 유지`로 후보만 반려하고 기존 게시 혜택은 유지한다.

아직 승인하지 않은 신규·변경 후보가 다음 정상 수집에서 사라지면 라이브 혜택에 반영하지 않고 자동 반려하며 `MISSING_FROM_LATEST_SOURCE` 사유와 최신 source bundle hash를 기록한다. 연결된 기존 게시 혜택까지 사라진 경우에는 별도의 삭제 의심 후보가 생성된다. 반대로 삭제 의심 혜택이 공식 목록에 다시 나타나면 대기 중인 삭제 후보를 `REAPPEARED_IN_SOURCE` 사유로 자동 반려한다. 이미 만료가 확정된 혜택이 재등장하면 일반 신규·변경 후보 경로를 통해 다시 게시할 수 있다. 출처 실패나 일부 수집 성공은 삭제 또는 자동 반려 근거로 사용하지 않는다.

T우주 구형 seed ID를 현재 안정 ID로 교체하는 명시적 데이터 이관은 일반 삭제 감지와 별개이며, 새 안정 ID가 게시된 경우에만 구형 항목을 만료한다.

## 운영 확인

`/admin/promotions`에서 후보별 source bundle hash, 보존 문서 version과 URL, 저장 원문 JSON, 공식 근거 문장, 필드 diff, 근거 누락과 고위험 삭제 차단 사유를 확인한다. 저장 원문 API는 관리자 인증과 `private, no-store`를 적용하고 HTML도 JSON 문자열로 반환해 같은 origin에서 실행되지 않게 한다. 일반 차단 후보는 단건·일괄 승인에서 모두 제외되며 반려만 가능하다. `removedFromSource` 삭제 후보만 전용 확인 동작으로 게시 혜택 만료를 명시적으로 승인할 수 있다.

원문 보존이 곧 혜택 정확성의 완전한 보증은 아니다. 기간형 공지의 공시일·효력 기간 교차 검증, 필드별 의미 입증 강화와 실제 공식 fixture 기반 회귀 검사는 계속 확장한다.
