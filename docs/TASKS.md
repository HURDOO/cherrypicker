# Cherrypicker 실사용 작업

## 상태 규칙

- `[ ]`: 일반 대기
- `[-]`: 현재 진행 중
- `[>]`: 사용자가 승인한 단 하나의 다음 작업
- `[~]`: 보류. 다시 활성화하기 전에는 진행하지 않음
- `[x]`: 완료 조건을 모두 검증한 작업

작업을 시작할 때 `[>]`를 `[-]`로 바꾸고, 완료 조건을 모두 관찰·실행한 뒤에만 `[x]`로 바꾼다. 후속 작업을 확정했을 때만 하나의 `[>]`를 새로 지정한다.

## 현재 기준선

로그인 없는 로컬 workspace, 공용 카탈로그, 조합 추천, 결제 기록, 선택적 계정 동기화, 카드·프로모션 수집·검수·revision·rollback 기반은 이미 구현되어 있다. 아래 목록은 이 기반을 재구축하는 작업이 아니라 비공개 실사용까지 남은 사용자 흐름을 완성하는 순서다.

  - 중간 입력이 있는 상태에서 새로고침·탭 전환·외부 앱 왕복 후 재개하며 이미 저장한 선택이 유지된다.
  - 설정 단계마다 주소가 바뀌고 브라우저 뒤로가기·앞으로가기로 단계와 저장된 재개 지점이 함께 이동한다.
  - 초기 설정 완료 후 다시 강제하지 않고, 설정 화면에서 누락 항목을 나중에 보완할 수 있다.
  - 주요 행동을 키보드로 완주하고 포커스·레이블·터치 타겟과 모바일 텍스트 잘림을 확인한다.

  - 필수 근거가 없거나 오류가 남은 후보는 게시하지 않고, 실패·미승인 후보가 기존 게시본을 변경하지 않는다.
  - 원문 의미 hash가 같은 카드는 AI를 재호출하지 않고, 남은 API credit을 넘는 지출은 사용자 승인 없이 하지 않는다.

  - 복원 임시 DB에서 quick check·foreign key·migration 호환성·핵심 레코드를 검증하고, 실행 중인 운영 DB를 임의로 덮어쓰지 않는다.

## [>] TASK-08 — 확실한 삭제 감지 후보를 자동 만료

- 범위: 정상적으로 완결된 공식 출처 수집에서 반복적으로 사라진 게시 프로모션을 증거 기반으로 자동 승인·만료해 관리자 검수 큐의 반복 작업을 줄인다.
- 선행 조건: 출처 실패·부분 수집·오래된 source bundle은 삭제 근거로 사용하지 않고, 자동 처리 기준과 감사 기록을 기존 삭제 감지 정책에 명시한다.
- 산출물:
  - 자동 승인에 충분한 반복 관측·source bundle·수집 완결성 판정
  - 자동 reviewer와 처리 근거가 남는 게시 혜택 만료 경로
  - 재등장·부분 실패·근거 부족 후보를 자동 승인하지 않는 회귀 테스트
- 완료 조건:
  - 기준을 충족한 삭제 후보만 자동 승인되어 연결된 게시 혜택이 `EXPIRED`가 된다.
  - 자동 처리 시 reviewer·처리 시각·source bundle hash와 판단 근거를 조회할 수 있다.
  - 출처 실패, 부분 수집, 한 번의 누락, 재등장 후보는 기존 게시 혜택을 유지한다.
  - 관리자 단건·일괄 수동 처리와 기존 감사·rollback 계약이 유지된다.
  - 관련 회귀 테스트와 `npm run lint`, `npm test`, `npm run build`가 통과한다.
