# 두산베어스 KB카드 결제 상황 후보 검토 — 2026-09-12

## 판정

`TASK-10`의 실제 `kb_doosan_bears` 후보는 아직 게시할 수 없다. 저장된 공식 원문과 [현재 KB국민카드 상품 페이지](https://card.kbcard.com/CRD/DVIEW/HCAMCXPRICAC0076?cooperationcode=02219&mainCC=a)를 대조해 결제 상황의 범위·요율·한도를 격리 제안으로 재구성했다. 할인받은 거래 전체를 전월 이용실적에서 제외하는 공통 계산기는 이후 구현했으나, 실제 후보에는 아직 정책·공식 근거를 반영하지 않았다. 금액 영향 `unsupportedClauses`는 그대로 두고 게시를 차단한다.

실제 DB의 카드 `DRAFT`와 기존 후보 `8e9d8ebb-3311-49e9-a438-e983d6a5900e`의 `PENDING` 상태는 그대로 유지했다.

공식 페이지의 정규시즌 홈경기 각주는 **티켓 항목에만** 붙어 있다. 굿즈와 F&B에 이를 전파하지 않는다. 지정 판매처는 실제 상점으로서 등록할 필요가 확인되기 전까지 가상 공개 브랜드로 만들지 않고, 사용자가 구매 상황과 승인 경로를 확인하도록 한다. 신규 카드 사용등록 유예로 전월 실적이 30만원 미만이면 30만원 구간 서비스를 제공하되 해당 월 한도는 절반이다.

## 격리 검증

- 기존 DB 후보·원문은 읽기 전용으로 조회했다. 격리 제안 파일은 `/private/tmp/cherrypicker-doosan-review.tfBoR6/candidate-proposal.json`에만 만들었다. 실제 후보 행, 카드 상태, 공개 catalog는 변경하지 않았다.
- 티켓·굿즈·F&B를 각각 `purchaseScenario`로 분리하고 티켓·굿즈에 같은 `usageGroupId`와 월 한도 공유 필드를 지정했다. 기존 근거를 재연결하고 질문별 공식 인용을 추가한 범위 후보는 규칙 10개, 근거 83개, validation 오류 0건, audit 누락·차단 0건이었다.
- 실제 계산기로 실적 0/30만/80만원, 신규 유예 절반 한도, 티켓 결제 후 굿즈의 공유 한도 소진, F&B 별도 한도 등 9개 경계를 검증했다. `src/utils/doosan-purchase-scenario.test.ts`에는 같은 의미의 독립적인 회귀 테스트를 고정했다.
- 제안 파일에는 할인 적용 거래의 실적 제외를 `affectsValue=true` 미지원 문구로 명시했다. 따라서 최종 후보 validation은 의도대로 게시 차단 오류 1건이며, `audit`만 0건인 것을 승인 가능 판정으로 해석하지 않는다.
- 공통 실적 정책 구현 뒤 저장된 공식 원문과 격리 후보를 다시 읽기 전용으로 대조했다. 할인 적용 매출 전체 제외·무이자할부·상품권의 공식 인용이 연결된 정책 2개를 격리 후보에 합성하니 정책 자체의 validation·audit 차단은 0건이고 카드 정책 추가 diff는 `HIGH`였다. 다른 실적 제외 항목과 취소·매입 시점까지 전수 해결한 것은 아니므로 기존 금액 영향 `unsupportedClauses`를 유지해 최종 validation은 계속 게시 차단 1건이다. 격리 리허설 스크립트는 `/private/tmp/cherrypicker-performance-policy.ob9sPd/doosan-policy-rehearsal.ts`에 남겼다.

## 남은 게이트

1. 공통 실적 정책과 기록 경로는 구현했지만 실제 두산 후보의 공식 제외 항목을 정책 데이터·인용으로 전수 구성하고, 할인 적용·미적용·거래 종류 식별 시 추천→기록→다음 달 실적을 끝까지 검증해야 한다. 기존 공개 카드 14장은 별도 제외 정책이 없어 새 결제의 승인금액을 기본 예상 실적에 반영한다.
2. 수정된 후보를 다시 전체 validation·근거 audit·대표 거래·기록 후 재계산으로 검증하고, 실제 관리자 검수 경로에서 사람의 범위·질문·한도 확인을 받는다. 안전한 후보 저장·수정 경로 없이 DB JSON을 직접 덮어쓰지 않는다.
3. 계정 기록 경로는 `SCENARIO` 대상 미지원 상태이며 인증된 관리자 화면과 실기기 추천·기록도 아직 확인하지 않았다. 실제 후보 게시와 유료 AI 재호출은 각각 별도 승인 전 실행하지 않는다.
